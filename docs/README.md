# Documentation

Documentation records durable project knowledge, not a duplicate of source code. Read `AGENTS.md` first, then open only the document relevant to the task.

- `architecture/`: stable architectural principles and boundaries.
- `development/`: workflow, validation approach, and current project state.
- `design/`: design knowledge confirmed from the visual source.
- `decisions/`: Architecture Decision Records (ADRs) for meaningful choices and their rationale.

Git history records what changed. `status.md` records the current state. Avoid docs that merely restate code or speculate about features that do not exist.
